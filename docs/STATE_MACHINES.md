# State machine map

[Architecture](ARCHITECTURE.md) · [Room behavior](OWN_ROOMS.md) · [Concert stability](CONCERT_STABILITY.md)

This map follows the SvelteKit site, Worker, Core and host recovery in the source reviewed at `d011f36`, with the directory change described below. It covers lifecycles with meaningful event ordering, time, retries, cancellation, permissions or visible transitions. Each row groups related transitions with the same owner. Static validation, simple preferences, one-shot requests and ordinary CRUD are outside the inventory. Tests named below are places to verify transitions, independent of production status.

**Implicit** means the phase must be inferred from fields, timers or callbacks. **Mixed** means named states cover part of the lifecycle. **Explicit** means the main phases already have names and a clear owner. Arrows summarize important paths and omit some transitions.

## Decision and review checks

Use a feature-owned named state when mutually exclusive phases currently have to be inferred. Keep independent facts, such as a pending read and freshness of the last result, separate. For shared systems, first name the view of existing authority and test the observed transitions. Change stored states or transport contracts only when a verified problem requires it.

The directory is the first change because a failed read was presented as a current empty list. Its existing read owner can fix that locally. The directory may keep displaying a stale snapshot while a retry is pending, and fresh empty is shown only after a successful response. Existing filtering, joining and creation remain available.

Room/concert playback, Discord recovery and authorization have the highest cost of a mistaken transition. For changes there, trace the initiating event, authority, freshness/revision guard and observable result. Test delayed success, failed recovery and scope change through the existing entry point. Preserve both user intent and actual readiness when they can differ. Playlist import and admin commands already separate reads from mutations; model any new view phase at that existing owner.
